Baymax Guide System — How It Works

From JSON step definition → Chrome message → GCP page animation

Full System Flow — What happens when a step becomes active
1
JSON step loads in Guidance/index.jsx
STEPS[stepIndex] gives the current step object — its selector, urlPattern, advanceOnUrlPattern, action, url. This is the source of truth for everything that follows.
2
URL check — "Are you on the right page?"
getCurrentGcpUrl() reads the active tab URL.
→ URL matches advanceOnUrlPattern? Step already done → skip forward.
→ URL fails urlPattern? Wrong page → show lost mascot + "Take me back".
→ URL ok? Continue to highlight.
3
Chrome message sent to GCP tab
highlightStep(step) calls chrome.tabs.sendMessage() to every frame in the tab (top + all iframes). Message contains: action:"highlight", selector, title, message, stepNumber, cheer.
4
Content script finds the element
findElement(selector) splits by comma and tries each CSS selector with document.querySelector() left-to-right, stopping at first match. Special prefix text:Cloud SQL scans all links/buttons by visible text.
5
Shadow DOM overlay injected
A hidden host <div> with a Shadow DOM is appended to the GCP page body. Inside: a pulsing red border box over the element + the Baymax mascot beside it. GCP's CSS cannot leak in; our styles cannot leak out.
6
Event watchers attached
watchElement(el) adds a capture-phase click listener on the element. If action:"fill", watchFill(el) also listens for input events (debounced 1.1s). These send BAYMAX_GUIDE_CLICKED / BAYMAX_GUIDE_FILLED back to the panel.
7
Step completes → auto-advance
Any of three signals triggers autoAdvance(): user clicks element, user types in input, or tab URL matches advanceOnUrlPattern. An advancedRef guard ensures only the first signal advances — duplicates are dropped.
8
Overlay cleared, next step loads
clearOverlay() removes the red box and mascot from the Shadow DOM. stepIndex increments, the effect re-runs from step 1 with the new step's JSON data.
What each JSON field controls
titleShown in the side panel's TaskStepCard header AND in Baymax's speech bubble on the GCP page. Also read aloud by speakText() if voice is on.
descriptionThe body text below the title — in the panel card, the mascot bubble, and the voice narration.
action click "Do it for me" calls el.click() after a 600ms highlight.
fill "Do it for me" uses the native HTMLInputElement.prototype.value setter then fires input + change events (React-compatible).
highlight "Do it for me" is hidden — step only highlights the element.
selectorComma-separated CSS selectors tried left-to-right by document.querySelector(). First match wins. text:Cloud SQL is a special prefix that searches by visible text content instead.
valueOnly for action:"fill" steps. The text programmatically typed into the input by "Do it for me".
urlThe exact GCP URL this step lives on. Used by goToStepPage() when "Take me back" can't use browser history.
urlPatternRegex tested against the current tab URL each time the step loads. Fails → show lost mascot. No urlPattern = any page is ok (Steps 1 & 2).
advanceOnUrlPatternRegex tested against the tab URL. Matches → step is DONE, auto-advance. Used to skip already-completed steps when the guide resumes, and to detect completion via navigation.
Three layers a step passes through
📄 Layer 1 — cloudSqlPostgres.js (JSON)
Declares what to do: selector, action, urlPattern, advanceOnUrlPattern. The only file you edit to fix or update the guide.
↓
⚛️ Layer 2 — Guidance/index.jsx (React, side panel)
Reads the JSON. Checks URLs. Sends Chrome messages to the GCP tab. Listens for completion events. Manages stepIndex state and progress in localStorage.
↓
🔌 Layer 2.5 — guide.js (Chrome API bridge)
Wraps chrome.tabs.sendMessage(), chrome.tabs.query(), chrome.tabs.onUpdated. Broadcasts to all frames. Returns {ok: true} or {error: '...'}.
↓
🌐 Layer 3 — guide-overlay.js (content script, GCP page)
Receives the message. Runs document.querySelector(). Injects the Shadow DOM overlay. Draws the pulsing red box + Baymax mascot. Attaches click/input listeners. Sends completion events back.
3 ways a step can complete (first one wins)
🖱️
User clicks the highlighted element
Content script's watchElement(el) fires in capture phase → sends BAYMAX_GUIDE_CLICKED → panel's onGuideStepEvent checks selector match → autoAdvance().
⌨️
User types into a highlighted input
watchFill(el) listens for input events, debounced 1.1s → sends BAYMAX_GUIDE_FILLED → panel calls autoAdvance(). Only on fill steps.
🔗
Tab URL changes to the step's destination
chrome.tabs.onUpdated fires on every navigation → stepCompletedByUrl() tests against advanceOnUrlPattern → autoAdvance(). Catches cases like clicking a search suggestion.
🛡️ advancedRef guard: all three paths call the same autoAdvance(). The ref is checked first — if already true, the call is dropped. Prevents double-advancing when a click and a URL change fire at the same time.
"Do it for me" — automation path
1
User clicks "Do it for me"
handleDoItForMe() sets automating=true, calls runStepAction(step).
2
Chrome message sent: action "click" or "fill"
Determined by step.action. Sent to all frames in the GCP tab.
3
Content script executes
click: highlights 600ms → el.click().
fill: native setter → dispatch input + change events (React-compatible).
4
Panel auto-advances after 800ms
setTimeout(autoAdvance, 800) — gives GCP time to navigate before incrementing stepIndex.
All animations in the system
baymax-pulse — element highlight
Red border box over the GCP button. box-shadow breathes in/out every 1.4s. Injected into Shadow DOM. Positioned using getBoundingClientRect().
baymax-bob — mascot figure
🤖
The Baymax SVG figure floats up and down 7px every 2.6s. Stops when mascot is .baymax-offscreen (element scrolled out of view).
bcBlink — chip eyes (Landing page)
Eyes stay open for 90% of a 6s cycle, then scaleY(0.1) at 95% — a realistic blink. Defined in BaymaxAnimated.jsx.
baymax-wiggle — sign board
Step 3 of 9
The "Step X of Y" board rocks −3° to +2° every 3.2s. Applied to .baymax-board inside the Shadow DOM.
bcGlow — chip body (Landing page)
The chip card's box-shadow pulses green every 4s. Defined in BaymaxAnimated.jsx injected CSS.
SVG arm wave — pointing arm
Arm rotates
−4° → −16° → −4°
every 1.6s
Uses SVG <animateTransform> — not CSS. Mascot flips via .baymax-flip class so the arm always points at the target.
All GCP page animations (pulse, bob, wiggle, pop, arm wave) live inside guide-overlay.js OVERLAY_CSS string and are scoped to the Shadow DOM — isolated from GCP's own styles.
